**ალბათობა:** Very High | **ზემოქმედება:** High | **პრიორიტეტი:** P0

## R-04: ქართული მონაცემთა დაცვის კანონთან შეუსაბამობა

### კანონი

**2023 წლის პერსონალურ მონაცემთა დაცვის კანონი (No. 3144/2023)** სრულად ჩაანაცვლა 2011 წლის კანონი. უმეტესი დებულებები ძალაში შევიდა **2024 წლის 1 მარტს**. ეს არ არის მომავალი კანონმდებლობა — ეს მოქმედი კანონია.

## R-05: GDPR-ის გავრცელება

**ალბათობა:** Medium | **ზემოქმედება:** Critical | **პრიორიტეტი:** P1

### როდის ვრცელდება GDPR შენზე

GDPR (მუხლი 3) ვრცელდება არა-EU კომპანიებზე, როდესაც:

1. **სთავაზობენ საქონელს/მომსახურებას EU რეზიდენტებს** — ინდიკატორები: EU ენები საიტზე, EUR ფასები, EU-ზე ორიენტირებული მარკეტინგი
2. **აკვირდებიან** EU პირთა ქცევას — ანალიტიკა, cookies, თრექინგი

### შენი ექსპოზიცია

ამჟამად შენი პლატფორმა მხარს უჭერს ქართულს (ka) და ინგლისურს (en). თუ EU მომხმარებლები აღმოაჩენენ და გამოიყენებენ შენს პლატფორმას (რასაც ინგლისურის მხარდაჭერა შესაძლებელს ხდის), GDPR შეიძლება გავრცელდეს. იმ მომენტში, როცა EUR ფასებს დაამატებ ან EU ქვეყნებში დაიწყებ მარკეტინგს, ნამდვილად გავრცელდება.

### GDPR მოთხოვნები ქართული კანონის მიღმა

| მოთხოვნა | გავლენა |
|----------|---------|
| EU წარმომადგენლის დანიშვნა (მუხლი 27) | ხარჯი + ადმინისტრაციული ტვირთი |
| მონაცემთა დაცვის ოფიცერი (შესაძლოა) | დამოკიდებულია დამუშავების მასშტაბზე |
| 72-საათიანი დარღვევის შეტყობინება | საჭიროა incident response პროცესი |
| მონაცემთა გადატანის უფლება (მუხლი 20) | საჭიროა data export ფუნქციის აგება |
| წაშლის უფლება (მუხლი 17) | ანგარიშის წაშლა არსებობს, მაგრამ სისრულის დადასტურება საჭიროა |
| ჯარიმები გლობალური ბრუნვის 4%-მდე ან 20 მლნ EUR | ეგზისტენციალური სტარტაპისთვის |

### მიტიგაცია

MVP-სთვის: უზრუნველყავი ქართული კანონის შესაბამისობა (რომელიც არსებითად GDPR-თან ჰარმონიზებულია). დაამატე data export endpoint. თუ/როცა მიზანმიმართულად EU მომხმარებლებს მიმართავ, გააკეთე სრული GDPR შეფასება.

## R-16: Data Export (Portability) არ არსებობს

**ალბათობა:** Medium | **ზემოქმედება:** Medium | **პრიორიტეტი:** P2

### ხარვეზი

არ არსებობს endpoint ან ფუნქცია, რომელიც მომხმარებლებს მონაცემების ექსპორტის საშუალებას მისცემს (სანიშნეები, მონიშვნები, ჩანაწერები, კითხვის პროგრესი, თარგმანის ისტორია). ქართული კანონიც და GDPR-იც მოითხოვს მონაცემთა პორტაბელობას.

### იმპლემენტაცია

ააგე `/users/me/export` endpoint, რომელიც აბრუნებს ZIP-ს:
- მომხმარებლის პროფილის მონაცემები (JSON)
- კითხვის ჩანაწერები, სანიშნეები, მონიშვნები (JSON)
- თარგმანის ისტორიის მეტამონაცემები (JSON)

## Vendor-ების მონაცემთა დამუშავება

ეს მესამე მხარის სერვისები ამუშავებენ მომხმარებლის მონაცემებს:

| Vendor | რა მონაცემებს იღებენ | მათი როლი |
|--------|---------------------|-----------|
| AWS S3 | ატვირთული ფაილები, თარგმანები, აუდიო | Data processor (შენახვა) |
| Anthropic (Claude) | წიგნის სრული ტექსტი თარგმნისთვის | Data processor (დამუშავება) |
| Google Cloud TTS | ნათარგმნი ტექსტი აუდიოს გენერაციისთვის | Data processor (დამუშავება) |
| ElevenLabs / Azure TTS | ნათარგმნი ტექსტი აუდიოს გენერაციისთვის | Data processor (დამუშავება) |
| Resend | მომხმარებლის email მისამართები | Data processor (email-ის მიწოდება) |
| BOG Pay / TBC Pay | გადახდის ტრანზაქციის მონაცემები | Data processor (გადახდები) |
| Sentry | შეცდომების ლოგები (შეიძლება შეიცავდეს მომხმარებლის კონტექსტს) | Data processor (მონიტორინგი) |

**შენიშვნა:** Google Cloud TTS-ის დოკუმენტაციაში ნათქვამია, რომ ტექსტსა და აუდიოს default რეჟიმში არ ლოგავს. ეს კარგია privacy-სთვის. გადაამოწმე ეს ElevenLabs-ისა და Azure-ისთვისაც.

თითოეული ეს ურთიერთობა უნდა იყოს დოკუმენტირებული, და უნდა გადაამოწმო, რომ მათი data processing ხელშეკრულებები ფარავს შენს ვალდებულებებს ქართული მონაცემთა დაცვის კანონით.
