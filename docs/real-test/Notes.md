# Search Input

url: `/ka/search`

1. ძებნა მუშაობს.
2. შედეგებში ყოველთვის მხოლოდ `20` წიგნი ჩანს, სხვადასხვა query-ის შემთხვევაშიც.
3. უნდა შემოწმდეს, კოდში წერია თუ არა ძიების შედეგების hard limit `20`.
4. თუ ასეთი limit არსებობს, უნდა მოიხსნას ან შეიცვალოს pagination-ით.
5. უკეთესი UX-ისთვის შეიძლება თითო გვერდზე მხოლოდ `10` შედეგის ჩვენება და ქვემოთ pagination-ის დამატება.
6. input-ის გასუფთავების შემდეგ შედეგები არ ნულდება.
7. საჭიროა `Clear` ღილაკი, რომ მომხმარებელმა სწრაფად გაასუფთაოს query და შედეგებიც განულდეს.
8. მოძებნილ წიგნზე დაჭერისას ფუნქციური გარე ლინკი არ არის.
9. წიგნის card-ზე ან სათაურზე დაჭერისას უნდა იხსნებოდეს გარე წყაროს ლინკი:
Amazon
Google Books
Open Library
10. გარე ლინკი უნდა იხსნებოდეს ახალ tab-ში და მიმდინარე ვებსაიტი არ უნდა იხურებოდეს.
11. მოსაფიქრებელია `Save` ფუნქცია, რომ მომხმარებელმა მონიშნოს საინტერესო წიგნი და მერე დაუბრუნდეს ძებნის ხელახლა გაკეთების გარეშე.
12. `Save` ფუნქციასთან დაკავშირებით დასაზუსტებელია API დატვირთვა: შესაძლოა მხოლოდ reference/link/book id-ის შენახვა იყოს საკმარისი.

# Upload Screen

url: `/ka/upload`

1. როცა მომხმარებელი logged out არის და ცდილობს ატვირთვას, error შეტყობინება მოდის ინგლისურად: `Authentication required`.
2. თუ ქართული ლოკალი არჩეულია, ეს შეტყობინება ქართულად უნდა მოდიოდეს.
3. გადასახედია ყველა `error`, `warning`, `success` შეტყობინება ყველა ლოკალზე სრულად არის თუ არა ნათარგმნი.
4. როცა მომხმარებელი დალოგინებულია და ცდილობს წიგნის ატვირთვას, progress ძალიან სწრაფად ადის `90%`-მდე და იქ ჩერდება.
5. უნდა გაირკვეს ეს რეალური upload progress-ია თუ UI-ს placeholder პროგრესია.
6. თუ პროგრესი რეალურ ატვირთვას არ ასახავს, საჭიროა უფრო სანდო და გასაგები loading UX.
7. წარმატებული ატვირთვის შემდეგ შეტყობინება, რომ მალე მოხდება redirect, კარგია, მაგრამ უფრო გასაგები იქნება თუ ქვემოთ დაემატება loader/progress bar.
8. ასეთი progress bar მომხმარებელს აჩვენებს, რომ არაფრის დაჭერა საჭირო არ არის და redirect ავტომატურად მოხდება.
