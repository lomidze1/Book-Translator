## 9. როგორ ვამოწმებთ

### 9.1 რა გვაქვს ახლა

`Translation` ცხრილში ინახება:

| ველი | რას ინახავს |
|---|---|
| `inputTokens` | Claude input ტოკენები |
| `outputTokens` | Claude output ტოკენები |
| `totalTokensUsed` | ჯამი |
| `translationType` | FAST / STANDARD |
| `qualityScore` | Gemini judge-ის საშუალო |

### 9.2 ⚠️ გაზომვის ხარვეზები

| # | ხარვეზი | გავლენა |
|---|---|---|
| **M1** | **cache ტოკენები არ ინახება.** `usageOf()` მხოლოდ `input_tokens`-ს კითხულობს. Anthropic-ის API-ში `input_tokens` **არ შეიცავს** `cache_read_input_tokens`-სა და `cache_creation_input_tokens`-ს | DB **ნაკლებად** აჩვენებს რეალურ ხარჯს |
| **M2** | Gemini judge-ის ტოკენები საერთოდ არ ინახება | judge-ის ხარჯი უხილავია |
| **M3** | ხელახალი თარგმანების ტოკენები `Translation`-ს არ ემატება | კვოტის რეალური ხარჯი უხილავია |
| **M4** | `tokensUsed` input-ისა და output-ის ჯამია — ერთი რიცხვიდან ფასის უკან გამოთვლა შეუძლებელია | უკვე ცნობილია (კომენტარი კოდში) |

**გასაკეთებელი:** `Translation`-ს დაემატოს `cacheReadTokens`, `cacheWriteTokens`,
`judgeTokens`, `retranslationTokens`, და `usageOf()` სრული `usage` ობიექტი წაიკითხოს.
სანამ ეს არ გაკეთდება, DB-ის ციფრი ხარჯის **ქვედა ზღვარია**, არა რეალური ხარჯი.

### 9.3 ყოველთვიური შედარება

**ნაბიჯი 1.** DB-იდან ავიღოთ დათვლილი ხარჯი:

```sql
SELECT
  DATE_TRUNC('month', "createdAt") AS month,
  "translationType",
  COUNT(*) AS translations,
  SUM("inputTokens")  AS input_tokens,
  SUM("outputTokens") AS output_tokens,
  ROUND((SUM("inputTokens") * 2.0 + SUM("outputTokens") * 10.0) / 1000000.0, 2) AS usd_lower_bound
FROM "Translation"
WHERE status = 'COMPLETED'
GROUP BY 1, 2
ORDER BY 1 DESC;
```

**ნაბიჯი 2.** Anthropic Console → Usage → იმავე თვის ფაქტობრივი ხარჯი.

**ნაბიჯი 3.** სხვაობა = cache ტოკენები + ჩავარდნილი მცდელობები + ხელახალი
თარგმანები. **თუ სხვაობა 20%-ს აღემატება — მოდელი გადასამოწმებელია.**

### 9.4 ერთეულის ეკონომიკა თითო თარგმანზე

```sql
SELECT
  t.id,
  b."pageCount",
  t."translationType",
  ROUND((t."inputTokens" * 2.0 + t."outputTokens" * 10.0) / 1000000.0, 3) AS cost_usd,
  p.amount AS revenue_gel,
  ROUND(p.amount / 2.611 - (t."inputTokens" * 2.0 + t."outputTokens" * 10.0) / 1000000.0, 2) AS margin_usd
FROM "Translation" t
JOIN "Book" b ON b.id = t."bookId"
LEFT JOIN "Payment" p ON p."translationId" = t.id AND p.status = 'COMPLETED'
WHERE t.status = 'COMPLETED'
ORDER BY margin_usd ASC
LIMIT 50;
```

`margin_usd ASC` — ყველაზე ზარალიანი თარგმანები ზემოთ. ეს კითხვა თვეში
ერთხელ უნდა გაშვდეს.

### 9.5 რეკომენდებული დამცავი მექანიზმები
