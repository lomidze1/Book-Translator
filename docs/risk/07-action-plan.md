# პრიორიტეტული სამოქმედო გეგმა

## მიმოხილვა

ეს არის „ახლა რა უნდა გავაკეთო?" დოკუმენტი. ქმედებები დაჯგუფებულია გადაუდებლობის მიხედვით და დალაგებულია რისკის შემცირებით ძალისხმევის მიხედვით.

---

## ფაზა A: Launch-მდე (სავალდებულო)

ეს პუნქტები უნდა დასრულდეს, სანამ რომელიმე საჯარო მომხმარებელი შეხვდება პლატფორმას. მათ გარეშე პირველი დღიდან სამართლებრივი პასუხისმგებლობის ქვეშ ხარ.

### A1. პროდუქტის პოზიციონირების ცვლილება

**მიმართული რისკი:** R-01, R-02 | **ძალისხმევა:** დაბალი (პროდუქტის გადაწყვეტილება, არა კოდი)

**ქმედება:** გადაპოზიციონირება „ქართული ნათარგმნი წიგნების მაღაზიიდან" „კერძო წიგნის თარგმანის workspace-ად."

| ცვლილება | ამჟამინდელი | სამიზნე |
|----------|-----------|--------|
| გაზიარებული კატალოგი | მომხმარებლებს შეუძლიათ სხვების თარგმანების ყიდვა | თითოეული თარგმანი კერძოა ატვირთვის მომხმარებლისთვის |
| „არსებული თარგმანის ყიდვა" (5 ლარი) | აქტიური | **გათიშული**, სანამ სალიცენზიო შეთანხმებები არ იქნება |
| „ბაზაში არსებული ინგლისური წიგნის ყიდვა" (1$) | აქტიური | **გათიშული** ან შეზღუდული public domain-ით |
| თარგმანის საკუთრება | პლატფორმას ეკუთვნის თარგმანები | მომხმარებელს ეკუთვნის თავისი თარგმანი |

**სტატუსი (2026-08-18):** გადაყიდვის (resale) მომხმარებლისთვის ხილული ზედაპირი მოხსნილია:
წაიშალა „არსებული თარგმანი მზადაა" ღილაკი წიგნის გვერდიდან, `PURCHASE_ORIGINAL` /
`PURCHASE_TRANSLATION` ტიპები web/mobile კლიენტებიდან და `CreatePaymentDto`-დან
(API აღარ იღებს მათ), ასევე resale-ის i18n გასაღებები (ka/en). Backend ლოგიკა
(`isResaleEnabled()`, ფასები, purchase completion handler-ები) და Prisma `PaymentType`
enum შენარჩუნებულია `ENABLE_BOOK_RESALE` flag-ის უკან — ლიცენზირებული კატალოგის
მოდელზე გადასვლისას ჩართვა შესაძლებელი იქნება flag-ით + კლიენტის ზედაპირის აღდგენით.

### A2. სამართლებრივი გვერდები

### A3. Upload Disclaimer და Copyright Warranty

**მიმართული რისკი:** R-01 | **ძალისხმევა:** დაბალი

```

    საავტორო უფლებებით დაცული მასალის ავტორიზაციის გარეშე ატვირთვა არღვევს ჩვენს მომსახურების პირობებს.
```

ეს checkbox არ აღმოფხვრის შენს პასუხისმგებლობას, მაგრამ აჩვენებს კეთილსინდისიერებას და პასუხისმგებლობის ნაწილს მომხმარებელზე გადააქვს.

### A4. Reader Authorization-ის გამოსწორება

**მიმართული რისკი:** R-07 | **ძალისხმევა:** დაბალი (კოდის ცვლილება)

წიგნის ownership-ის ვერიფიკაციის დამატება ყველა Reader სერვისის მეთოდში (bookmarks, highlights, notes, reading progress). ეს ნახევარი დღის სამუშაოა.

```typescript
// დაამატე BookmarkService-ში, HighlightService-ში, NoteService-ში, ReadingProgressService-ში
private async verifyBookAccess(userId: string, bookId: string) {
  const userBook = await this.prisma.userBook.findFirst({
    where: { userId, bookId },
  });
  if (!userBook) throw new ForbiddenException();
}
```

## ფაზა C: 30-90 დღე (გამაგრება)

### C1. ანტივირუსული სკანირება

**მიმართული რისკი:** R-08 | **ძალისხმევა:** საშუალო

ClamAV-ის ინტეგრაცია upload pipeline-ში. ფაილების სკანირება parsing რიგში შესვლამდე. ინფიცირებული ფაილების უარყოფა მკაფიო შეცდომის შეტყობინებით.

### C2. Data Export Endpoint

**მიმართული რისკი:** R-16 | **ძალისხმევა:** საშუალო

ააგე `/users/me/export`, რომელიც აბრუნებს ZIP-ს მომხმარებლის მონაცემებით (პროფილი, სანიშნეები, ჩანაწერები, მონიშვნები, კითხვის პროგრესი, გადახდის ისტორია JSON-ად).

### C3. Audit Logging

**მიმართული რისკი:** R-18 | **ძალისხმევა:** საშუალო

`AuditLog` ცხრილის დამატება და ძირითადი მოქმედებების ლოგირება: upload-ები, თარგმანები, გადახდები, წაშლები, ანგარიშის ცვლილებები. ეხმარება compliance გამოძიებებს და debugging-ს.

### C4. Vendor-ების ჯანმრთელობის მონიტორინგი

**მიმართული რისკი:** R-11 | **ძალისხმევა:** დაბალი-საშუალო

- შეტყობინებები vendor API ჩავარდნებზე

### C5. გადახდის მიწოდების ლოგირება

**მიმართული რისკი:** R-12 | **ძალისხმევა:** დაბალი

## ფაზა D: მასშტაბის ეტაპი (90+ დღე)

### D1. Provider Abstraction

**მიმართული რისკი:** R-11, R-19 | **ძალისხმევა:** მაღალი

თარგმანის აბსტრაქცია provider ინტერფეისის უკან, რათა შეძლო გადართვა Claude-ს, Google Gemini-ს ან სხვა LLM-ებს შორის. ახლა გადაუდებელი არ არის, მაგრამ მნიშვნელოვანია მასშტაბირებისას.

### D2. გამომცემლებთან მიმართვა

**მიმართული რისკი:** R-01, R-02 | **ძალისხმევა:** მაღალი (ბიზნეს განვითარება)

თუ market fit ვალიდირებულია:
1. ყველაზე მოთხოვნადი წიგნების იდენტიფიკაცია მომხმარებლის მონაცემებიდან
2. ქართულ გამომცემლებთან მიმართვა თარგმანის უფლებებისთვის
3. თვითგამოცემის ავტორებთან მიმართვა (უფრო მოქნილი)
4. Revenue-share მოდელის აგება
5. ლიცენზირებული კატალოგის შექმნა კერძო თარგმანის workspace-ის პარალელურად

### D3. GDPR მომზადება

**მიმართული რისკი:** R-05 | **ძალისხმევა:** მაღალი

თუ EU მომხმარებლებზე ფართოვდები:
- EU წარმომადგენლის დანიშვნა (მუხლი 27)
- მონაცემთა დაცვის ზემოქმედების შეფასება
- Cookie-ს თანხმობის მექანიზმი
- გაძლიერებული data subject rights იმპლემენტაცია

### D4. Secret Rotation

**მიმართული რისკი:** R-17 | **ძალისხმევა:** საშუალო
